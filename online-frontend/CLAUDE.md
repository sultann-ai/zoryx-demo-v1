# Zoryx — Customer website (online-frontend)

Public ordering site for Zoryx (Zoryx). Independent package: no workspaces, **never import from `../pos-frontend` (the POS) or `../backend`**. Run, deploy and QA steps are in README.md. Source of truth for brand, palette and UX: `docs/ONLINE_SITE_BRIEF.md` — read it before any UI work.

## Stack
React 19 + Vite + TypeScript, react-router-dom (route chunks are lazy except Home, whose below-the-fold sections are a lazy chunk too), @tanstack/react-query, Tailwind v4 (colour tokens generated into `src/brand/theme.css` from `src/brand/brand.config.ts`; shape/type/spacing tokens in `src/index.css` `@theme`), self-hosted fonts (DM Sans and Bricolage Grotesque from Fontsource; Urdu is ONE weight of Noto Nastaliq, subset by scripts/subset-urdu-font.py, never fake a bold), oxlint. No UI kit, icon font, carousel library, axios or analytics. `sharp` is a devDependency used only by `scripts/make-assets.mjs`.

## Commands
`npm run dev` · `npm run build` (tsc -b + vite build → `dist/`) · `npm run preview` · `npm run lint` · `npm run typecheck` · `npm run theme` (writes `src/brand/theme.css`; also runs before dev and build) · `npm run assets` (regenerate favicon, 192/512 + maskable icons, web manifest and og-image from `src/brand/logo.svg` and the brand colours; outputs are committed).
Always finish a task with build, lint and typecheck.

## Hosting
Vercel project with Root Directory `online-frontend`. `vercel.json` holds the SPA rewrite and the Content-Security-Policy (no inline scripts/styles: keep it that way; the API origin appears twice in the CSP and must match `VITE_API_URL`). The backend's `CORS_ORIGIN` must list the site origins. Env (`.env.example`): `VITE_API_URL`, `VITE_SITE_URL`. See README.md.

## Rules (from the brief, short)
- Urdu first, right-to-left (`<html lang="ur" dir="rtl">`); big English/اردو toggle on every page. Strings live in `src/i18n/ur.ts` + `en.ts` (same keys); use `const { t } = useT()`. Urdu is spoken-style and needs native proofreading.
- Logical CSS only (`ms-/me-/ps-/pe-/start-/end-`); mirror directional icons with `mirror`. Prices: `formatRs()` → "Rs 1,450", Western digits, `text-ink` bold (never the action colour).
- Mobile first at 360px (works at 320). 48px tap targets (`min-h-touch`). Photos and icons, few short words, one primary action per screen, a phone number always visible.
- Colour tokens only, all in `src/brand/brand.config.ts`: the brand `palette` (forest, lime, cream, ink, white; accents deep-green, tomato, sunflower, sky, in small doses) and the `theme` roles components use: canvas, band, surface, action (+ action-hover, on-action), accent, heading, heading-accent, promo, ink, muted, success, error, overlay. Target balance ~45% cream, ~40% green, ~8% lime, ~7% accents. **Lime (`promo`) only on forest/ink, never on cream or white** (on light use `sunflower` for a highlight, `success` for the "open" dot). Text on lime, sunflower and sky is ink; no white text on tomato below 24px bold. Small coloured text on light is `text-accent` (deep green); the accent word of a heading is `heading-accent` (tomato, large text only). **Tones:** a dark (forest/ink) surface carries `tone-dark`, which switches the primary fill to lime + ink and the heading, accent and focus-ring colours through `--tone-*` variables in `index.css`; a `.card`, a dialog or `.tone-light` inside it switches back. Never put a forest fill on ink (1.8:1). the phone header-card scrim is `bg-overlay/80..90`. Never convey meaning by colour alone. Visual language: brief §10; build with `src/components/ui/` (Button, Card, ProductCard, SectionHeader, ...) instead of ad hoc classes; no `!bg-*` overrides on buttons; no star ratings, review counts, hearts or time claims (the reference screenshots show them: we do not).
- Brand lives in `src/brand/`: `brand.config.ts` (names, tagline, colours: the one file to edit), `logo.svg` (the ONE replaceable logo file, a placeholder today; then run `npm run assets`), `Logo.tsx` (placeholder serif wordmark with an accent line; name from the store settings via `useShopName`, config as fallback) and `LogoMark`. Never import a logo image anywhere else. `src/brand/theme.css` is generated: do not edit it.
- **One-place brand change** (verified with a dummy brand): edit `brand.config.ts` (names, owner, tagline, colours) and replace `logo.svg`, then `npm run assets`. That regenerates `theme.css`, favicon, 192/512 and maskable icons, `site.webmanifest` and `og-image.png`; `vite.config.ts` fills `theme-color` and the `<title>`, description and og tags in `index.html` from the same config (`%BRAND_*%` placeholders: never type the shop name into `index.html`). The header, footer and photo stand-ins read the name via `useShopName`/`Logo`.
- `.btn-secondary` / `.btn-ghost` take the surface's strong colour (forest on light, cream inside `tone-dark`) from the components layer, so a `text-*` utility still overrides them. Contrast is computed in `docs/ONLINE_SITE_BRIEF.md` §10.8; keep text at 4.5:1 and never put opacity on text over a fill.
- Known leftovers: `_coming-soon.html.bak` is an unused old backup with its own palette.
- No accounts, dropdowns, captchas, popups, cookie banners, third-party scripts or runtime font requests.
- Errors say what to do next (retry + call us). API errors are `{ error, code? }`; money fields are strings; image URLs are relative to the API origin (`apiUrl()`).
- **localStorage only for language, cart, saved details, last order, the order history and the vibration switch** (`mc.haptics`, "0" = off) (`mc.orders.v1`: the last 10 orders placed from this phone, with names, total and the cart lines for Reorder; always in try/catch).
- Budgets: landing ~120 KB gzip JS, menu ~150 KB.
- Shop phone is a placeholder in `site.config.json` — it feeds the call links, footer and `<noscript>`.
- Home hero (768px and up): the green band (`bg-forest` + `tone-dark`: cream headline, lime accent line and primary pill, lime fact icons) with just the rider PNG beside the text. There is NO background video, poster, panel, circles or other decoration there (all removed on purpose: they looked wrong). Do not add them back without being asked. `lib/heroTone.ts` is `'dark'` to match: the header takes the hero's forest at the top of Home. The status chip sits in a fixed 48px slot so its arrival never moves the headline. The only video is the phone Home's header card (below), which the owner asked for.

If the file is missing nothing renders. Decorative (no alt), absolutely positioned in a fixed 4:3 box (no layout shift).
- Home layout (top to bottom): Header, split green Hero (text + status chip + real facts on the start side, the rider on the end side), then two runs in `components/home/BelowFold.tsx`: `.home-sections.home-bands-start` (Categories, New arrivals (isNew), Best sellers (isFeatured), Offer banner (announcement and/or first deal with a photo, wave edge via `--next-bg`), Order by deal (categories stand in when there are no deals)) and `.home-sections.home-bands-end` (Why, How, Reviews, Gallery, Find us). The colours go by what is rendered (`index.css`: `.home-bands-start` counts from its first section, so cream sits next to the green hero; `.home-bands-end` counts from its last, so Find us is always cream above the footer; Why is `data-band="forest"` wherever it lands), so two neighbours never share a background. Do not give a section its own fixed band. Padding is `--spacing-section` (clamp 56-112px) with the `--spacing-gutter` sides. The root font size is 18px, so px-exact design tokens are in px, not rem. Urdu text needs `line-height: 2` (already forced in `index.css`); don't fight it per component.
- Cart: `src/cart/` (CartProvider, `useCart`, `useResolvedCart`). localStorage key `mc.cart.v1` holds ids + quantities only (`{v:1, lines:[{kind, id, variantId, addOnIds, qty}]}`); names, photos and prices are re-read from the live menu, and invalid stored data is ignored. Checkout must send `items: [{menuItemId, quantity, variantId?, addOnIds?}]` and `deals: [{dealId, quantity}]` built from these lines; never a price.

An order saved without `lines` simply has no Order again.

Every sheet/modal owns ONE history entry while open via `lib/useHistoryLayer` (Menu, the phone cart host, the QR sheet, the gallery), so browser/Android Back closes it; a flow that swaps one sheet for another keeps `active` true so it stays one entry, and checkout navigates to the order page with `replace`. `lib/useSheetLock` (used by `Sheet` and the gallery) stops page scroll and sets `html[data-sheet-open]`, which hides the tab bar.
- **Home item sections** (`components/home/ItemRows.tsx`): "Fresh on the menu" (isNew) and "Everyone's favourites" (isFeatured); their bands come from the rhythm above. A grid of `PreviewCard`s: 1 column under 480px, 2 to 768px, 3 to 1024px, 4 above; fewer cards keep their column width at the start. While the menu loads, one row of `ProductCardSkeleton`s (as many as the columns). Badges come from the item (Popular if `isFeatured`, New if `isNew`) and `ProductCard` sorts every card's badges Popular, New, Deal.
- **"Why Zoryx"** (`WhySection` in `components/home/Sections.tsx`): a green band (`data-band="forest"` + `tone-dark`), the four `FeatureCard`s in a grid of 1 column under 560px, 2 to 1024px, 4 above. Scroll-in reveals use `lib/useRevealOnce` (ref on the container, `.reveal-item` on the items: fade and rise 16px, 500ms, once; `--dur-reveal` / `--stagger` tokens, nothing hidden without JS or with reduced motion); every below-the-fold Home section uses it (header, then content) and any later scroll-in must too, never a per-item inline delay (the CSP forbids inline styles).
- **"How to order"** (`HowSection` in `components/home/Sections.tsx`): band from the rhythm, the three steps in their order, no cards. Under 768px a vertical stepper (56px circle at the start, text beside it), from 768px three columns; a 2px dashed forest line (40%) joins circle centre to circle centre behind the circles (`.how-step::after`, `--how-gap` / `--how-circle` in `index.css`). Scroll-in once via `useRevealOnce`: step, line, step, line, step, one `--stagger-step` (220ms) apart; lines draw with `clip-path` (mirrored in RTL); static under reduced motion. Step text is DM Sans 700 18px with `text-balance`.
- **"What our customers say"** (`ReviewsSection` in `components/home/Sections.tsx`): band from the rhythm; the layout follows the count: 1 review centred at max 640px, 2 in two columns (stacked under 560px), 3+ a 3-column grid from 1024px and a native `snap-row` below (keyboard-focusable with a name while it scrolls; no JS, no arrows, no carousel).
- **"Find us"** (`FindSection` in `components/home/Sections.tsx`, `#find`): always the last band, so cream; one white `rounded-panel` (24px) card, address on the start side, opening hours and the delivery areas on the end side from 768px (stacked below), each an `InfoBlock` (IconCircle, `.eyebrow` label, value). Values the staff have not filled in (`lib/placeholders.ts`: blank or the backend's seeded "coming soon" texts, kept in step with `SETTINGS_PLACEHOLDERS` in `siteContent.service.ts`) show as a muted pill with a clock; empty hours show that pill once, without the "Opening hours" label. Below the card: Call (primary, number in `.num`), WhatsApp and Open in Google Maps (secondary), full width and stacked on phones, inline from 768px. No map embed.
- **Website header (768px and up, `components/Header.tsx`)**: sticky; transparent at the top of the page (forest on Home, matching the green hero), solid past 24px of scroll (`bg-canvas`, hairline `border-ink/10`, `shadow-soft`, `--dur-header` 200ms, zero under reduced motion). Over the dark Home hero it carries `tone-dark` and the reversed logo; `lib/heroTone.ts` (`HOME_HERO_TONE`, now `'dark'`) must match the hero (change both together). The logo link is a container: under 100px only `LogoMark` shows; the logo is never stretched or shadowed. Round icon buttons use `.icon-btn` (48px, hairline edge, tone colours); `LanguageToggle` takes the look through `className` (the phone app bar keeps its default). The cart count is a lime badge with ink text and an ink ring (its edge on the light header). Under 400px "Order now" becomes a round bag icon with the label `sr-only` (same link).
- **Phone app shell (< 768 px)**: `components/Shell.tsx` picks `DesktopShell` (the website header/footer, unchanged) or the lazy `components/mobile/MobileShell` (fixed app bar + tab bar, same routes) by `lib/useAppMode`'s `useIsPhone()` (`max-width: 767px`, same split as Tailwind `md`). Routes added for it: `/orders` (redirects to the last order within 48 h, else an empty state) and `/more`. No router migration: `MobileShell` intercepts internal link clicks and runs the navigation inside `lib/navTransition` (View Transitions API, else the `.page-enter` CSS animation); Back/popstate gets the CSS animation only. `lib/scrollMemory` keeps each tab's scroll position (tab roots are keyed by path, other pages by history entry). Layout rules: bar heights are written in px (the root font is 18px, so `h-14` is 63px); phone-only styling uses `max-md:` and the CSS variables `--header-h`, `--tabbar-h`, `--sab` in `index.css`; `env(safe-area-inset-*)` for bars and sticky bars; `dvh`/`svh`, never `vh`; fixed things above the tab bar use `bottom-[var(--tabbar-h)]`. Installed mode (`useStandalone`, `html[data-standalone]`) hides install prompts. Text that must stay selectable (order code, account numbers, address) gets `.selectable`. Do not add swipe gestures: the browser's edge-swipe back must keep working and tabs are not swipeable.
- **Phone polish (< 768 px)**: *Motion* uses only the tokens in `index.css` (`--dur-press` 150 ms for presses and small changes, `--dur-sheet` 220 ms for sheets, pages-as-sheets and pops, `--dur-page` 300 ms for page transitions, `--dur-fill` for the order progress line, `--ease-out`); reduced motion zeroes them all, so never hard-code a duration or a cubic-bezier (use `duration-[var(--dur-press)]` etc.). Every tappable element gets a press scale from one zero-specificity rule (`:where(button, a[href], summary, ...):active`). Sheets rise and pages slide in via `.sheet-rise` / `.sheet-page` (set by `Sheet`); the drag-to-close follows the finger and leaves at the flick's speed. `Photo` shows the placeholder colour and fades the image in. The cart tab and the mini-cart pop on each add (`cart/useCartBump`). *Snackbars* are one system (`lib/toast` + `components/mobile/ToastHost`): `showToast({ message, kind, action, onClose })`, one at a time, above the tab bar and mini-cart (`PageToasts`), or above a sheet's footer while a sheet is open (`SheetToasts`, inside every `Sheet`); cart removals (with Undo), copy confirmations and errors use it; the action runs before `onClose`. *Haptics*: `lib/haptics.vibrate()` is called on add-to-cart (`CartProvider.add`) and when an order is placed; it is guarded (no Vibration API on iPhones), switchable in More > Settings (only shown where the API exists), default on. *Full-screen states* are `components/mobile/AppState` (offline with the cart kept and a retry, error, empty menu/cart, not found, ordering closed at checkout) and `Splash` (the brand mark while a screen's code first arrives); `ErrorState` and `NotFoundOrder` switch to them on phones. *Bars*: `html` has `scroll-padding-top/bottom` for the app bar, tab bar and mini-cart, `--minicart-h` gives the page room while the pill shows, and the shell scrolls a focused field to the middle of the visible area (also on `visualViewport` resize) while the tab bar hides until the field loses focus.

The screenshot upload is `uploadPaymentProof` (POST `/api/online/orders/:publicId/payment-proof`, one JPEG/PNG/WebP up to 5 MB, 409 when the order no longer waits for payment). The Orders tab shows a dot while the newest recent order is not Delivered/Cancelled. `routes/More.tsx` is a grouped settings-style list: a two-button language switch, Call, WhatsApp, Find us (inline: address, hours, areas and fees), Install (the browser's own prompt where `lib/useInstall` captured `beforeinstallprompt`, else a Share > Add to Home Screen sheet for iPhone or a browser-menu sheet elsewhere; hidden when installed), How ordering works, Clear my saved details (clears `mc.details.v1` only; the history and cart stay).

Every section shows a fixed-size skeleton while loading and renders nothing when empty (heights are px: the root font is 18px). The video: `public/media/drone.mp4` + `drone-poster.jpg` (both optional; without them the card is a plain dark panel). Rules in `HeaderCard.tsx`: the poster paints first, the file is only requested after the page `load` and while the card is on screen, no autoplay on reduced motion / data saver / 2G-3G (the play button starts it on request), it plays only while half the card is visible and the tab is in front, and a missing or broken file removes the video and its button.

## Design system rules (kept from the final design pass; details in brief §10)
- **Tokens only.** Colours (from `brand.config.ts`), radii (`rounded-inner` 12px, `rounded-card` 20px, `rounded-pill`, `rounded-tile`, `rounded-t-sheet`), the two ink-tinted shadows (`shadow-soft` resting, `shadow-raised` hover), the type scale (`text-h1/h2/h3`, fluid; Urdu has its own smaller h1/h2; `text-button` 15px; `.num` for prices: DM Sans 700 tabular; `.eyebrow`), tap sizes (`touch` and `tap` are both 48px; every button is at least 48px, `size="lg"` 56px), the gutter (`px-gutter`, clamp 16-40px), section padding (`py-section`, clamp 56-112px), a 4px scale (`p-4x`, `gap-6x`, ...: Tailwind's numeric spacing is 4.5px steps because the root is 18px) and the container (`max-w-page`, `max-w-page-padded` = page + gutter, paired with `px-gutter`) are tokens in `index.css` `@theme`. Fonts loaded: DM Sans 400/500/700, Bricolage Grotesque 800 (headings), the one Nastaliq weight; nothing else. No `#hex`, `rgb()`, `rounded-[..]`, `shadow-md/lg`, `bg-white`, `text-white`, `bg-black`, no inline `style` for look (the only hex values live in `brand.config.ts` and its generated `theme.css`). Text on action/accent/error/success is `text-on-action`; card backgrounds are `bg-surface`. A grep for the old names (maroon, gold, field) and for hex/rgb in `src`, `index.html`, `scripts` must find nothing outside `src/brand/`.
- **Buttons only through `components/ui/Button*`** (or `buttonClass()`); the `.btn*` classes belong to `buttonClass()`. Variants: `primary` (the surface's fill: forest/cream on light, lime/ink inside `tone-dark`), `secondary` (outline), `ghost`, `icon`. Dark surfaces (`bg-ink`, forest) get `tone-dark`; never override a button colour with `!bg-*`. Shared primitives: `SectionHeader` (eyebrow, two-tone title with the accent word inline, action; start-aligned, action on the same row from 768px), `Badge`, `Chip`, `Card`, `IconCircle`.
- **`Icon`**: a `className` without its own `size-*/w-*/h-*` keeps `size-6`. Use `mirror` for forward arrows and `flip` for the "back" arrow. Icon-only controls need an `aria-label`.
- **`<html lang/dir>` is set in a layout effect** (`i18n/LanguageProvider.tsx`) so the saved language is on the page before first paint. Do not move it back to `useEffect`: English visitors would get a frame of Urdu layout and a large layout shift.
- **Nothing that depends on the store/menu data may push the page down.** The Home announcement is an overlay on the top of the hero (the hero leaves room); skeletons match the final size (`ProductCardSkeleton`, `StatusChip`). Every `<img>` has `width`/`height`; below the fold it is `loading="lazy"`.
- **`.snap-row` lives in the components layer** so `lg:grid` / `md:overflow-visible` can turn a scroll row into a grid.
- **Reduced motion:** the global rule in `index.css` also sets `animation-iteration-count: 1`; new animations need no extra handling, but never rely on motion to convey state.
- **Motion:** one easing curve, `--ease-out` in `@theme` (so Tailwind's `ease-out` and every bare `transition-*` utility use it, default 200ms); transitions use the `--dur-*` tokens (150-250ms). Headings get `text-wrap: balance` from the base rule (no orphaned last word). `html, body` have `overflow-x: clip` at every width.
- **Floating WhatsApp** (`components/WhatsAppButton.tsx`, website layout only; styles in `.wa-float`): 56px at the bottom-end, 16px plus the safe-area insets from the edges, z-40, a 2px cream ring so it shows on green bands, ink focus ring outside it; `wa-lift` raises it above the menu/order bottom bars; it fades out (`wa-away`) while the footer is on screen so it never covers the footer (which has its own WhatsApp link); one pulse 3s after load, none under reduced motion.
- **Fonts preloaded:** `vite.config.ts` (`fontPreloads`) writes the built URLs of the first-screen fonts into `<meta name="font-preload-ur|en">`; `public/early-hints.js` preloads the set for the saved language (`mc.lang`, Urdu default): Nastaliq for Urdu, DM Sans 400/700 + Bricolage 800 for English. If the font imports in `index.css` change, update the patterns there (the build fails loudly otherwise).
- **Strings:** after changing `src/i18n/*.ts` run `npm run strings`; new section titles are a `title` + `accent` key pair (accent = second line, placeholder until the owner confirms).
- **Layout checks worth repeating after UI changes** (320, 360, 768, 1280 px, Urdu and English): no horizontal scroll, tap targets ≥ 47px, Urdu text ≥ 18px, no clipped Nastaliq, one shared left edge for header/strip/chips/sections, CLS ~0 on a production build (`vite build` + `vite preview`, not the dev server: dev injects CSS late and overstates shift).
